# **Key Domain**

## **Overview**

The `KeyDomain` is a `ScriptableObject` that serves as the **Source of Truth** for a specific category of Semantic Keys (e.g., "Stats", "Audio", "AIStates").

It maintains a list of `KeyDefinition` objects, ensuring that every key has a unique **GUID** (Identity) and a **Name** (Value). The domain also handles the generation of static C\# classes for compile-time safety.

## **Strict Inspector**

The default Unity Inspector is disabled for `KeyDomain` assets to prevent accidental corruption of GUIDs. The custom "Strict Inspector" provides a safe interface for mutation operations.

### **Domain Settings**

| Action | Description |
| ----- | ----- |
| **Rename** | Renames the Domain, the Asset File (`.asset`), and the generated static class (`.cs`). **Warning:** If you rely on `[SemanticKeyFilter("Name")]` in your code, you must update those strings manually after renaming. |
| **Generate Static Class** | Compiles the current list of keys into a `static readonly` C\# class (e.g., `Stats.cs`). This allows you to use keys in code (e.g., `Stats.Strength`). Once the class exists, adding, renaming or deleting keys regenerates it. |
| **Update All References** | Triggers the `SemanticKeyReferenceUpdater` tool. This scans the entire project for "Stale" keys (valid GUIDs with outdated string names) and synchronizes them with this Domain. |

### **Key Management**

Keys are displayed in a read-only list by default. You must enter "Edit Mode" to modify them.

#### **1\. Adding Keys**

* Click **\+ Add New Key** at the bottom of the list.  
* Duplicate names (case-insensitive) are rejected to prevent ambiguity. In a key field's dropdown, **\+ Add Key** with a name that already exists selects the existing key.  
* If the static class exists, it is regenerated with the new key.

#### **2\. Finding References (Magnifying Glass)**

Before modifying a key, click the **Magnifying Glass** icon.

* This scans all Prefabs, ScriptableObjects, and open Scenes for usages of this specific Key GUID.  
* If references are found, the objects are selected in the Project/Hierarchy view.

#### **3\. Renaming Keys**

* Click **Edit** next to a key.  
* Modify the name and click **Save**.  
* **Impact:** The GUID remains unchanged, but the cached string value in your project's Prefabs becomes "Stale."  
* **Automatic Updates:** Saving the new name regenerates the static class (if it exists) and runs **Update All References**, which updates the cached values in Prefabs, ScriptableObjects and open Scenes. Scenes that aren't open keep the old value.  
* Code that uses the old field name (e.g., `Stats.Strength` after renaming "Strength" to "Might") stops compiling until you update it.

#### **4\. Deleting Keys**

* Click **X** next to a key.  
* **Safety Check:** The tool performs a deep scan of the project to count active references.  
* **Consequences:**  
  * If references exist, the tool will warn you that deleting the key will reset those fields to `SemanticKey.None` (null).  
  * Unlike ScriptableObjects, deleting a Semantic Key does not cause missing reference exceptions, but logic relying on that specific key will fail.  
  * If the static class exists, it is regenerated without the key, so code that uses the key's field stops compiling.

## **Runtime Performance**

The `KeyDomain` maintains an internal `Dictionary<string, KeyDefinition>` cache.

* **Lookup Cost:** **O(1)**.  
* **Initialization:** The cache is built on `OnEnable` (when the domain is loaded).  
* **Usage:** This is primarily used by the Editor Dropdown to populate lists quickly, and by the `SemanticKeyInjector` for validation. Runtime game logic typically does not query the Domain directly, relying instead on the cached values within the `SemanticKey` structs.

## **Code Generation Details**

When you click **Generate Static Class**, the system:

1. Locates the folder defined in `SemanticKeysSettings` (default: `Assets/Scripts/AutoGenerated`).  
2. Sanitizes the Domain Name to create a valid C\# class name (e.g., "Player Stats" \-\> `PlayerStats`, "3D Assets" \-\> `_3DAssets`). A domain name with no letters or digits logs an error and nothing is generated.  
3. Sanitizes Key Names to create valid C\# fields (e.g., "Critical Hit %" \-\> `Critical_Hit_`, "default" \-\> `@default`). A field name already taken by an earlier key, or by the class itself, gets a numeric suffix (e.g., `Stats_1`), and a key name with no letters or digits becomes `Key`.  
4. Writes a file containing `public static readonly SemanticKey` fields. Key names are escaped in the string values, so quotes and backslashes are safe. If the file is already up to date, it is left untouched (no recompile).

The domain's own GUID is saved with the asset, so regenerating the class doesn't change it. Domains saved with older versions of the package get a GUID the next time they are loaded in the Editor; save the project to keep it.

**Example Output:**

 namespace Game.Constants  
 {  
     using SemanticKeys;
 
     public static class Stats  
     {  
         public static readonly SemanticKey Strength \= new SemanticKey("guid-1...", "Strength", "domain-guid...");  
         public static readonly SemanticKey Agility \= new SemanticKey("guid-2...", "Agility", "domain-guid...");  
     }  
 }
