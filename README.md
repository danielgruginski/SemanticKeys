# **Semantic Keys**

**Semantic Keys** is a Unity architecture package designed to eliminate "magic strings" from your codebase and Inspector while retaining the flexibility of string-based APIs (like Unity's Animator or TopDown Engine's MMEvent).

It replaces fragile string literals with a robust, GUID-backed SemanticKey struct. This ensures that renaming a key in the database updates all references safely, while maintaining **O(1)** runtime performance by caching the string value.

## **Features**

* **GUID-Backed Identity:** Keys are referenced by GUID. Renaming a key's display text does not break references in Prefabs or ScriptableObjects.  
* **Zero-Overhead Runtime:** The SemanticKey struct implicitly converts to string using a cached value. No dictionary lookups occur during Update loops.  
* **Inspector Integration:** Custom Property Drawer using Unity's AdvancedDropdown API. Support for searching, folders, and creating new keys directly from the Inspector.  
* **Code Generation:** Generates static readonly classes (e.g., Stats.Strength) for compile-time safety in C# scripts.  
* **Domain Filtering:** Restrict Inspector fields to specific domains using [SemanticKeyFilter].  
* **Settings:** Configurable paths for generated code and data storage.

## **Installation**

1. Open Unity and go to Window > Package Manager.
2. Click the + button in the top-left corner.
3. Select Add package from git URL....
4. Enter the repository URL: https://github.com/danielgruginski/SemanticKeys.git

The package is self-contained and has no external dependencies.

## **Usage**

### **1\. Creating Domains & Keys**

The system uses KeyDomain ScriptableObjects as the source of truth.

**Via Inspector (Recommended):**

1. Add a public SemanticKey MyKey; field to any MonoBehaviour.  
2. Click the dropdown in the Inspector.  
3. Select **\+ Create New Domain** to create a category (e.g., "Stats", "SFX").  
4. Select a Domain, then **\+ Add Key** to create a key (e.g., "Health").

**Via Project Window:**

1. Right-click in Project view \-\> Create \-\> SemanticKeys \-\> Key Domain.  
2. Name the asset (e.g., Stats).  
3. Add keys to the list manually.

### **2\. Using in Code**

The SemanticKey struct is designed to be a drop-in replacement for strings.

    using UnityEngine;  
    using SemanticKeys;
    
    public class PlayerStats : MonoBehaviour  
    {  
        // Allows selection of ANY key from ANY domain  
        public SemanticKey GeneralTag;
        
        // Only allows selection of keys from the "Stats" domain  
        [SemanticKeyFilter("Stats")]  
        public SemanticKey StatType;
    
        private void Start()  
        {  
            // 1. Implicit String Conversion  
            // Works directly with Animator, MMEvent, etc.  
            Debug.Log($"Selected Stat: {StatType}");   
              
            // 2. Comparison  
            // Compares GUIDs, not string values.   
            // Safe even if "Strength" was renamed to "Might" in the editor.  
            if (StatType == Stats.Strength)   
            {  
                ApplyMultiplier(2.0f);  
            }  
        }  
    }

### **3\. Code Generation**

To use keys in code (e.g., Stats.Strength instead of StatType), you must generate static classes.

1. Select a KeyDomain asset in the Project view.  
2. Click the **Generate Static Class** button in the Inspector.  
3. By default, code is generated in Assets/Scripts/AutoGenerated.

**Output Example:**

    // Generated file: Stats.cs  
    namespace Game.Constants  
    {  
        using SemanticKeys;
    
        public static class Stats  
        {  
            public static readonly SemanticKey Strength = new SemanticKey("guid...", "Strength", "domain_guid...");  
            public static readonly SemanticKey Agility = new SemanticKey("guid...", "Agility", "domain_guid...");  
        }  
    }

### **4\. Configuration**

You can customize where assets and scripts are stored.

1. Navigate to Assets/Data/SemanticKeys/ (default location).  
2. Select the SemanticKeysSettings asset (it is created automatically upon first use).  
3. Modify:  
   * **Domain Creation Path:** Folder for new SOs created via the dropdown.  
   * **Generated Code Path:** Folder for the static C# classes.  
   * **Generated Namespace:** Namespace for the static classes (default: Game.Constants).

## **Architecture**

### **The Problem**

Using strings for logic (animator.SetTrigger("Jump")) is fragile. A typo or a rename breaks the game silently. Using enums solves this but requires recompilation to add new types and cannot be easily used across loosey-coupled systems.

### **The Solution**

SemanticKeys creates a hybrid approach:

1. **Editor Time:** We map a **GUID** to a **String**. The Inspector serializes the GUID.  
2. **Runtime:** The struct holds the String. Implicit conversion returns this string immediately.

### **Performance**

* **Memory:** Struct size is roughly equal to 3 object references.  
* **CPU:** Passing a SemanticKey to a method expecting a string is effectively free (reference passing). There is **no** dictionary lookup or initialization cost at runtime.

## **Naming Conventions**

* **Dots in Names:** You can use dots in key names (e.g., UI.Labels.Title).  
* **Code Sanitization:** When generating code, dots are converted to underscores.  
  * Key: UI.Labels.Title  
  * Code: UILabelsTitle.cs (Class) / UI\_Labels\_Title (Field)
